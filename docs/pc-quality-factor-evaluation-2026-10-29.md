# PCでの通訳品質改善試験：背景・用語・訳出タイミングを分離

調査日：2026-10-29。追跡Issue：[同時通訳品質・遅延改善 #21](https://github.com/niho-life/niho-translate/issues/21)。実行手順は[評価ハーネス](../research/eval/README.md)。ここには集計だけを置き、原音声・原文・訳文・会話の個別内容はGit管理外に保管する。

## 目的と条件

品質を第一に、同じ非公開の日本語会話5分区間を実時間送信した。OpenAI `gpt-live-1`、日→英、`marin`、200 msフレーム、同一WAV・同一区間・同じ参考原稿を使う。製品相当の`plain-q`を基準とし、**一度に変える要素を一つ**にした。基準設定は保存済みの2runを再利用し、他条件は各1run。長い会話・録音・話者への一般化や実機の耳到達を証明する試験ではない。

| 条件 | `plain-q`から変えた点 |
|---|---|
| 基準1・2 | なし。モデル生成の揺れを見るため同条件を2回 |
| 用語だけ | 公開・合成の地名と不動産用語を追加。背景説明は入れない |
| 背景だけ | 話者・地域・会話の目的を短く伝える。用語リストは入れない |
| 話者の役割だけ | インタビュアーと不動産エージェントの役割を伝える。話題説明と用語リストは入れない |
| 話題だけ | 外国人の湘南エリアでの不動産購入という話題を伝える。話者の役割と用語リストは入れない |
| 訳出タイミングだけ | 安定した主題を先に訳し、未発話の述語・否定・数字は予測しない指示。背景・用語は入れない |

原文の参考原稿は42区間、うち意味採点対象41区間。既存の機械生成原稿で、一般名詞を固有名詞にした誤りと、否定の明らかな漏れ・誤タグを**全条件共通の私有コピー**で本文上補正した。区間の原文と時刻は変えていない。この補正は人手で元音声を校正したことを意味しない。

訳**音声**はローカルwhisper.cppで単語時刻化した。モデル字幕との語一致率は話者の役割だけが約92%、他条件は約98〜99%。同じ小型判定モデル `gpt-5.4-mini`・同じ採点指示・同じ修正版原稿で、意味、誤訳、欠落、`L_start`を一次比較した。小型判定モデルには、質問を陳述にしても高い意味点を付ける不整合があった。**以下の平均点は品質保証でも採用判定でもない**。個別の質問、否定、主体、固有名詞、発話にない補足を別に確認する。

## 一次結果

`L_start`は原語区間開始→対応する英語の**訳音声**の最初の語。p95は対応した区間だけで計算し、8秒以内率は未対応も分母に残す。`missing`は意味採点41区間のうち訳音声に対応できなかった数。

| 条件 | 意味平均 / 3 | `missing` | 重要事実の誤訳 / 事実の欠落 | `L_start` p50 / p95 | 8秒以内率 | 観察 |
|---|---:|---:|---:|---:|---:|---|
| 基準1 | 2.927 | 0 | 0 / 1 | 7.37 / 11.16秒 | 59% | 質問を陳述にする例あり |
| 基準2 | 2.732 | 0 | 0 / 4 | 6.02 / 8.71秒 | 85% | 同設定でも意味と速度が揺れる |
| 用語だけ | 2.732 | 0 | 0 / 3 | 6.52 / 16.47秒 | 78% | 固有名詞の別名化、条件・主体の欠落候補 |
| 背景だけ | 2.927 | 0 | 0 / 2 | 5.51 / 12.37秒 | 83% | 質問が改善した区間はあるが、未発話の情報を足した例あり |
| 話者の役割だけ | 2.488 | 2 | 0 / 8 | 7.07 / 25.01秒 | 54% | 音声認識が乱れ、重要な条件や時刻の欠落も増えた |
| 話題だけ | 2.683 | 0 | 1 / 5 | 7.18 / 17.82秒 | 61% | 数量の誤り1件、質問の回答化あり |
| 訳出タイミングだけ | 2.780 | 2 | 0 / 1 | 7.41 / 13.98秒 | 61% | 早出しと品質維持の両立は確認できず |

重要事実の「誤訳0」は、この参考原稿と小型判定器の自動件数である。固有名詞の別名化や、質問への回答化はこの列に収まらない。各条件1runの差はモデル生成の揺れと分離できず、**現時点で製品の既定指示を変更しない**。

### 精度の優先確認

誤りの起きやすい9区間だけを、より強い`gpt-5.4`でも同じ原稿・訳音声ASRで再判定した。対象を選んだ後の診断であり、5分全体の品質値ではない。基準2回の意味平均は1.89/3・1.78/3、背景だけは2.00/3、話者の役割だけは1.56/3、話題だけは1.67/3。話者の役割だけでは9区間中5件の音声ASRに不明瞭な語列が判定された。背景だけでは質問が正しい形になった区間があったが、話者の主体の誤り1件と、元音声にない「写真」を加えた例も判定された。基準2回にも質問を陳述にする例があり、話題だけでも質問の回答化が残った。**背景だけの数値上の小幅な改善を製品品質の改善とは認定できない。**

訳音声を小型ASRで読み取った文字列にも乱れがあるため、この判定は「訳音声から聞こえると思われる内容」の機械評価である。質問・主体・固有名詞・発話していない事実の追加は、採用前に日英話者が実音声を確認する。

## 事実そのものが聞こえるまで

会話中の、意味を左右する否定2件と数量1件を選び、日本語でその事実を言い終えた時刻から英語訳音声で**意味を確定する語**（否定なら `can't` / `don't`、数量なら `half`）を話し始める時刻までを`L_fact`とした。3件とも各runの文字上は正しく訳されている。`L_start`と違って、原文の長い前置きや日本語文末の否定を「まだ聞けない時間」として区別できる。語時刻と対応はASRを文字上で確認した段階で、音声の人手校正は未了。

| 条件 | 選んだ3事実の`L_fact` p50 / 最大 |
|---|---:|
| 基準1 | 4.19 / 7.70秒 |
| 基準2 | 4.94 / 5.22秒 |
| 用語だけ | 4.11 / 6.42秒 |
| 背景だけ | 5.13 / 9.87秒 |
| 話者の役割だけ | 3.69 / 5.23秒 |
| 話題だけ | 5.16 / 6.06秒 |
| 訳出タイミングだけ | 4.75 / 5.97秒 |

3件の最大値を全体のp95や品質保証と読み替えない。話者の役割だけはこの3事実を早く出したが、5分全体では欠落が増え、音声ASRも乱れた。正しい事実を出すまでの時間と、質問・主体・固有名詞が正しく伝わったかを同時に見る。

## 次の採否作業

1. 重要な誤り候補と、背景だけで改善した質問の訳音声を独立した強い判定器または日英話者が確認する。字幕だけで判定しない。
2. 話者の役割だけ・話題だけは今回の結果で採用候補から外す。背景だけを再検討する場合は、未発話の事実を足さない対策を独立に検証する。
3. 有望な条件だけ別録音・別話者で複数回再現する。品質の改善がない条件に速度だけを理由に昇格させない。
4. `L_fact`の語時刻を実音声で校正し、原文の述語・否定が現れる前に出た英語が推測でないか確認する。実iPhone・イヤフォンの追加遅延は別途測る。

DeepL Voiceは別系統の用語比較候補だが、訳音声APIを使えるプランとキーが現在確認できていない。[利用条件と制約](public-audio-software-evaluation-2026-10-29.md#deepl-voice比較の利用条件)を満たしてから同じ採点表へ加える。
