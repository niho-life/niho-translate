# ネイティブ日本語5分の音声通訳ストレス試験（2026-10-31）

## 目的と試料

現行候補のGPT-Live `plain-q`を、既存の不動産対談とは独立した日本語話者・内容で確かめた。試料は[京都大学のCoVoST 2 Native Japanese](https://github.com/ku-nlp/covost2NativeJa)のtest split（CC BY 4.0）から、文と英訳が付いた89発話を決定的な順序で選び、0.9秒の無音を挟んで300秒へ連結したもの。3人のネイティブ話者を含み、質問候補21件を配置した。否定候補23件・数量候補22件も文字列規則で分散させたが、義務形や慣用句も混じるため、これらを「事実ラベルが人手で確定した件数」とは扱わない。

独立した読み上げ文を連結しており、自然な対談や話者交替の検証にはならない。音声・原文・付属英訳・訳音声・区間別判定はGit管理外の私有研究フォルダに保存し、この公開リポジトリには入れない。

## 手順

24 kHz mono PCM16を200 msフレームで実時間送信し、末尾20秒の無音で残りの訳出を待った。出力**音声**をローカルwhisper.cpp `small.en`で単語時刻化し、CoVoSTの日本語文を参考原稿としてCodex判定器v3で89区間を照合した。付属英訳と日本語文を見て32発話の数字・否定・場所・条件・期限を33件の事実アンカーに指定し、同じ音声ASRで再判定した。遅延は原語区間開始から対応する英語音声の理想再生時刻までの`L_start`。字幕到着時刻は代用していない。原語転記の文字誤り率は、句読点・空白を除いたデータセット文と、モデルの逐次原文転記を連結した文字列とのLevenshtein距離で求めた。

| 項目 | GPT-Live `plain-q`、5分1回 |
|---|---:|
| 原語転記の文字誤り率 | 9.62%（137 / 1,424文字） |
| 対応づいた区間 | 88 / 89 |
| `L_start`中央値 / 95百分位 | 3.50秒 / 5.38秒 |
| `L_start` 8秒以内 | 87 / 88（98.9%） |
| 訳音声の再生待ち行列最大 | 0.78秒 |
| 意味点（0–3）の平均 | 2.44 / 3 |
| 意味3点 / 0–1点 | 59 / 89、18 / 89 |
| 質問候補のうち「質問を答えに変えた」判定 | 2 / 21 |
| 事実アンカーの正しい / 誤り / 判定不明 | 30 / 2 / 1（計33） |
| 欠落 / 創作の判定フラグ | 9 / 8 |
| 出力音声のローカルASRとモデル字幕の語一致 | 97.5%（coverage 93.5%） |
| fatal / 末尾切断警告 | なし / なし |
| API費用の推定 | 約$0.30 |

低評価には、徒歩所要時間の上限を正確な所要時間として述べ、歩く主体も付加した例、動物の親子関係を別の情景へ変えた例、質問を約束の文にした例、住宅設備を別の語として訳した例が含まれる。事実アンカーでも、対象を限定する表現を別の対象へ置き換えた判定がある。原文・付属英訳・音声ASRを89件並べた私有照合表を作成した。**速度はこの連結短文では目標に近いが、重大な意味誤りを許す品質ではない。**既存の自然会話5分では`L_start`の95百分位が8秒を超えるrunもあり、この試験の速度を製品の対面会話へ一般化しない。

## Kotoba STSとの同一音声比較

[fal上のKotoba STS](https://fal.ai/models/kotoba-technologies/kotoba-sts/v1/realtime_voice/api)へ上記と**同じ300秒の公開WAV**を200 msずつ実時間送信し、既定・先読み`delay=10`・`delay=20`を各1回試した。末尾20秒の無音、訳音声のローカルASR、同じCodex判定器v3と33事実アンカーを使った。各runの途中失敗・末尾切断警告はなく、提供字幕は英文だった。fal経路では日本語原文字幕を取得できなかった。

| 指標 | GPT-Live `plain-q` | Kotoba既定 | Kotoba `delay=10` | Kotoba `delay=20` |
|---|---:|---:|---:|---:|
| 意味点平均（0–3） | 2.44 | 1.90 | 2.17 | 2.06 |
| 意味0–1点 / 89発話 | 18 | 38 | 26 | 30 |
| 意味3点 / 89発話 | 59 | 33 | 43 | 37 |
| `L_start`中央値 / 95百分位 | 3.50 / 5.38秒 | 2.59 / 4.05秒 | 4.04 / 5.24秒 | 3.99 / 5.39秒 |
| 対応づいた発話 / 8秒以内 | 88 / 87 | 89 / 89 | 89 / 89 | 88 / 88 |
| 事実アンカー正しい / wrong / omitted / unclear | 30 / 2 / 0 / 1 | 27 / 2 / 1 / 3 | 30 / 1 / 2 / 0 | 31 / 0 / 1 / 1 |
| 質問の断定化フラグ | 2 | 2 | 1 | 2 |
| 欠落 / 崩れた英文フラグ | 9 / 3 | 16 / 18 | 15 / 6 | 23 / 17 |
| 理想再生の待ち行列最大 | 0.78秒 | 2.44秒 | 2.24秒 | 1.98秒 |
| 5分セッションの概算費用 | $0.30 | $0.19 | $0.19 | $0.19 |

`delay=10`はKotoba既定より意味点が高かったが、`delay=20`では再び低下した。各条件1回なので先読み値だけの因果効果は断定しない。Kotoba既定は速いが、品質優先の製品既定を置き換える根拠にならない。先読みを増やした2条件もこの試料ではGPT-Liveの意味点に届いていない。**APIが返した最初の音声チャンクは無音を含み得る**ため、`firstAudioOutMs`を英語発話開始として使っていない。

自動事実判定のKotoba `wrong` / `omitted`には、ローカル訳音声ASRが「否定」「3台」「年に一回」を落とした一方で、モデルの英文字幕には対応語がある区間を含む。別の区間では、誤った理由への置き換えが字幕と音声ASRに共通していた。全体の字幕・訳音声ASR語一致が97～98%でも、短い重要語の正誤は保証されない。両テキストと原音・訳音声の短い聴取パックをGit管理外に保存し、判定ファイルの数字は**未監査の自動値**として残した。

## 独立した自然な日本語対談5分

[声庭の公開対談](https://github.com/koniwa/koniwa)から既存の尼崎市長インタビュー300秒（CC BY 4.0、25意味区間・37事実アンカー）を使った。保存済みGPT-Live `plain-q`の訳**音声**を、Kotoba `delay=10`・`delay=20`の新規実時間runと同じローカルASR・Codex判定器v3・参考原稿で再採点した。各条件1回で、同じ区間24/25を採点できた。出力音声と日本語原音声、字幕、個別判定はGit管理外に保存する。

| 指標 | GPT-Live `plain-q` | Kotoba `delay=10` | Kotoba `delay=20` |
|---|---:|---:|---:|
| 意味点平均（0–3、採点24区間） | 2.46 | 1.92 | 1.83 |
| 意味0–1点 / 3点 | 4 / 15 | 7 / 5 | 6 / 2 |
| `L_start`中央値 / 95百分位 | 6.92 / 10.75秒 | 6.69 / 9.81秒 | 6.15 / 8.58秒 |
| 対応づいた区間の8秒以内 | 16 / 24 | 18 / 24 | 21 / 24 |
| 事実アンカー正しい / wrong / omitted / unclear | 36 / 1 / 0 / 0 | 30 / 4 / 2 / 1 | 32 / 2 / 3 / 0 |
| 欠落 / 崩れた英文フラグ | 0 / 1 | 3 / 2 | 3 / 1 |
| 理想再生の待ち行列最大 | 0.39秒 | 2.50秒 | 1.59秒 |
| 5分セッションの概算費用 | $0.28 | $0.19 | $0.19 |

この自然対談ではKotobaの訳音声開始がやや早かったが、**意味点と事実保持はGPT-Liveが上回った**。Kotobaでは日付、今後の予定、条件、話し手の帰属を落とす・変える候補があり、一部はモデル字幕と訳音声ASRの双方に現れた。`delay=10`の字幕と訳音声ASRの全体語一致は94%、`delay=20`は96%で、区間別の自動判定は聴取による確定前である。1回ずつなので順位の統計的確証にはならないが、品質優先の製品既定をKotobaへ変える根拠は得られなかった。CoVoSTは短文では全発話が8秒以内だった一方、この対談の95百分位はKotobaでも8秒を超え、**8秒以内を製品として満たしたとは言えない**。

### 重要な事実を話し終えた後の遅延

対談の訪問日・訪問先・開始月など確認しやすい**5事実だけ**を選び、`L_fact = 英語音声で対応事実を言い始めた時刻 − 日本語音声で事実を言い終えた時刻`を追加計測した。日本語は保存済みWhisper語時刻、英語は今回の訳音声ローカルASR語時刻へ手でindexを付け、正しい事実だけを速度成功例に含めた。誤訳・欠落は別件数に残す。

| 選んだ5事実の結果 | GPT-Live | Kotoba `delay=10` | Kotoba `delay=20` |
|---|---:|---:|---:|
| 正しい事実として時刻対応 / 誤訳 / 欠落 | 5 / 0 / 0 | 3 / 2 / 0 | 3 / 0 / 2 |
| 正しい事実だけの`L_fact`中央値 / 95百分位 | 3.54 / 13.91秒 | 3.56 / 6.08秒 | 2.63 / 4.46秒 |
| 日本語の事実完成より先に英語で話し始めた数 | 1 | 0 | 1 |

Kotobaの`L_fact`が短く見える表には**誤訳・欠落した2事実が速度の分母から外れる**選択効果がある。GPT-Liveの遅い1事実は開始月の訳を後置した例で、13.91秒だった。日本語の事実完成前に正しい英語が始まった例は先行予測として別に数えた。この5件はASRテキストと語時刻の照合のみで、原音・訳音声を人が聴いて時刻を校正していないため、実機の合格値ではない。

## 判定の限界と次の順序

原語文はデータセット付属文で、89音声を人がすべて聴き直した正解原稿ではない。英語音声のASRにも誤認識があり、意味点・フラグ・事実判定は機械評価である。事実アンカーは33件に限定し、別の事実誤りを網羅しない。元のアンカー無し判定にあった`criticalFactErrors=0`は**誤りゼロを意味しない**ため、上表ではアンカー有りの再判定のみを使った。付属英訳と訳音声を人が比較し、質問・主体・否定・数量の誤りを確定する必要がある。

この追加比較の主な遅延は原語の**区間開始→対応する訳音声開始**の`L_start`である。上記の自然対談5事実以外には`L_fact`を付けていない。原音声と訳音声を語単位で聴取校正してから対象を広げる。以前の別録音での少数事実の`L_fact`と混ぜない。

Kotobaを同じWAV・同じ判定器で比較し、品質優先の先読み設定も2段階試した。独立した自然対談でも同じ品質優先の結論だったが、モデル差の統計的確証には反復と人手聴取が必要である。日英話者のブラインド聴取と端末マイク・イヤフォンの耳到達実測まで、製品の既定エンジンは変えない。MSLTの自然会話コーパスもローカルに取得して連続5分の私有試料を作ったが、研究・非商用のライセンスなのでクラウドAPIへ送らず、権利条件を確認した範囲のローカル分析に留める。
